GitHub action :- it is GitHub built in ci/cd and automation tool that allow you to automate software workflows directly from GitHub repo using yaml files.
it can build , test , scan , and deploy applications automatically whenever certain events occur.

When a developer pushes code to GitHub, GitHub checks the event defined in the workflow file. If the event is push, the GitHub Action is triggered automatically. A temporary runner (usually Ubuntu) is created, and the repository code is downloaded into it. Then the required software (such as Python) and project dependencies are installed. After that, the build step is executed, which may involve installing packages, packaging the application, or building a Docker image. Next, GitHub Actions runs the testing command (for example, pytest), which executes the test files already written by the developer, such as test_login.py or test_user.py. If any test fails, the workflow stops and deployment is skipped. If all tests pass, GitHub Actions executes the deployment commands defined in the YAML file, such as deploying through Docker, SSH, Kubernetes, AWS, or Azure. If deployment succeeds, the workflow is marked as successful.



terms :- 

.workflows:- a workflow is the entire automation pipeline.
.event :- an event triggers a workflow(like push , pull , release).
. job :- job is a group of task executed on the same runner ( build , test , deploy ).

step:- smallest execution unit means each command is a step.
action :- reusable code block.                     
runner :- machine where workflow executes ( os like ubuntu  , windows , macos).

types of runners :- 
.GitHub hosted runner :- provided by GitHub ( window , ubuntu , macos) 
- no maintaince , easy setup
.self hosted runner :- company manages it's own server ( full control , private network access , maintaince required ).



*variable :- used for reusable configuration values. 
.defined once then used it in yaml files.
*secrets :- used to store sensitive information like passwords , api keys.
*inputs:-values provided by the user while running workflow .
*matrix strategy :- run the same job on multiple platforms (ubuntu , windows , macos ).
